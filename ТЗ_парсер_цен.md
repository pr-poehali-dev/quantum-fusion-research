# Требования к парсеру цен — интеграция с BeGraphics

Документ для команды, которая разрабатывает парсер.
Описывает, куда и в каком формате слать данные о ценах.

---

## 1. Куда и как слать данные

- **Метод:** `POST`
- **URL:** `https://functions.poehali.dev/505d6a55-4cdb-4d30-9e46-3292ad49b4ab`
- **Заголовки:**
  - `Content-Type: application/json`
  - `X-Parser-Token: <секретный токен>` — выдадим отдельно. Без него запрос отклоняется с кодом `401`.

**Тело запроса (JSON):**

```json
{
  "source": "DNS",
  "items": [
    {
      "name": "Видеокарта GIGABYTE GeForce RTX 4070 GAMING OC",
      "price": 54990,
      "sku": "1234567",
      "url": "https://www.dns-shop.ru/product/....",
      "in_stock": true
    }
  ]
}
```

**Успешный ответ:**

```json
{
  "ok": true,
  "processed": 1,        // сколько товаров принято
  "price_changes": 1,    // сколько совпало с нашими товарами
  "new_products": 0      // сколько новых (у нас таких нет)
}
```

---

## 2. Поля по каждому товару

| Поле       | Обязательное | Что это                                                                 |
|------------|--------------|-------------------------------------------------------------------------|
| `name`     | **да**       | Полное название товара как на сайте-источнике                           |
| `price`    | **да**       | Цена числом, в рублях, без пробелов и знака ₽ (например `54990`)        |
| `source`   | желательно   | Имя магазина-источника (на уровне всего запроса, не товара)             |
| `url`      | желательно   | Прямая ссылка на товар у конкурента                                     |
| `sku`      | желательно   | Артикул/код товара у источника                                          |
| `in_stock` | желательно   | `true` / `false` — есть ли в наличии                                    |

---

## 3. Главное правило — слать ТОЛЬКО изменения

- Парсер шлёт товар **только если цена изменилась** с прошлой проверки.
  Не нужно гонять всю базу каждый раз — фильтрация на стороне парсера.
- Идеальный режим: **раз в сутки утром** одним пакетом (батчем) собрать все
  изменения за ночь и отправить.

---

## 4. Вопросы к команде парсера

1. **Как часто** парсер сможет проверять цены — раз в день, чаще?
   В какое время удобно слать утренний батч?
2. **Сколько источников** (магазинов-конкурентов) планируете и какие именно?
   Будет ли в `source` стабильное имя для каждого?
3. **Объём:** сколько примерно товаров за один запрос — десятки, сотни, тысячи?
   (Нужно понять, не упрёмся ли в лимит времени одного запроса — возможно,
   придётся бить на пачки по N штук.)
4. **Артикул (`sku`):** реально ли его отдавать? С ним сопоставление с нашим
   каталогом будет точнее.
5. **Название:** насколько оно стабильно? Мы матчим товары по похожести
   названий, поэтому важно, чтобы оно было полным и не менялось произвольно.
6. **Формат цены:** гарантируете чистое число (без валюты, пробелов, копеек)?
   Как отдаёте цену со скидкой / без — нужна финальная цена для покупателя.
7. **Наличие:** сможете отдавать `in_stock`? Нужно ли различать
   «нет в наличии» и «товар снят»?
8. **Ошибки/повторы:** если запрос не дошёл (сеть, таймаут) — парсер умеет
   повторить отправку? Не будет ли дублей при ретраях?

---

## 5. Что происходит с данными на нашей стороне (для контекста)

- Каждое изменение сохраняется и сопоставляется с нашим товаром по названию.
- Цена продажи считается автоматически:
  **цена конкурента −7%, округление до 250 ₽**, и попадает в утренний список
  на подтверждение менеджером.
- Если товара у нас нет — он уходит в раздел «Новые товары».

---

## 6. Пример запроса (curl)

```bash
curl -X POST "https://functions.poehali.dev/505d6a55-4cdb-4d30-9e46-3292ad49b4ab" \
  -H "Content-Type: application/json" \
  -H "X-Parser-Token: ВАШ_ТОКЕН" \
  -d '{
    "source": "DNS",
    "items": [
      {"name": "Видеокарта GIGABYTE RTX 4070 GAMING OC", "price": 54990, "sku": "1234567", "url": "https://...", "in_stock": true}
    ]
  }'
```

> Токен (`X-Parser-Token`) выдаётся отдельно перед подключением.
