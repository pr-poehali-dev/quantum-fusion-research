# Промпт: сделать полную выгрузку проекта (база + файлы)

> Скопируй весь текст ниже и отдай своему ИИ-ассистенту в проекте на poehali.dev.
> Он сам всё напишет, задеплоит и отдаст ссылки.

---

Задача: сделать в проекте механизм ПОЛНОЙ выгрузки данных — дамп PostgreSQL
и все файлы хранилища — чтобы можно было развернуть копию проекта на своём
сервере. Ничего не спрашивай по мелочам, делай сразу целиком.

## Что нужно сделать

### 1. Бэкенд-функция `backend/export-data/index.py` (Python)

Доступ ТОЛЬКО по ключу: заголовок `X-Admin-Key` (или `?key=`), сверяется с
переменной окружения `ADMIN_KEY`. Иначе 403 — выгрузка содержит всю базу.

Действия через `?action=`:

| action | что отдаёт |
|--------|-----------|
| `info` | JSON: размер базы, список таблиц с числом строк, число файлов |
| `db` | дамп SQL: `CREATE TABLE` + `INSERT`. Параметры `&table=`, `&offset=`, `&limit=`, `&full=0` |
| `indexes` | индексы, внешние ключи, UNIQUE-ограничения (ставятся ПОСЛЕ данных) |
| `files` | JSON со всеми файлами хранилища и ссылками |
| `filelist` | те же ссылки простым текстом (для `wget -i`) |
| `script` | готовый `download.sh`, качающий все файлы |
| `readme` | инструкция по развёртыванию на своём сервере |
| `envfile` | `.env.example` со всеми переменными, которые читают функции |

Схему брать из `os.environ["MAIN_DB_SCHEMA"]`, подключение — `psycopg2`
и `os.environ["DATABASE_URL"]`.

### 2. Скрипт `scripts/скачать-данные.py`

Локальный скрипт: запускается как `python scripts/скачать-данные.py <ADMIN_KEY>`,
дёргает функцию, сам обходит лимиты и складывает результат в папку `выгрузка/`:
`dump.sql`, `indexes.sql`, `files/` (с сохранением структуры папок),
`README.md`, `.env.example`.

## Грабли, на которые НЕ надо наступать (проверено на боевом проекте)

1. **`pg_dump` в окружении функции недоступен**, а версия сервера может не
   совпасть с клиентской. Дамп собирай вручную: `information_schema.columns`
   → `CREATE TABLE`, `SELECT` → `INSERT`.

2. **`pg_get_constraintdef()` в облаке запрещён** (ошибка «is not whitelisted»).
   Внешние ключи и UNIQUE собирай из `information_schema.table_constraints` +
   `key_column_usage` + `constraint_column_usage` + `referential_constraints`,
   группируя колонки по имени ограничения (иначе развалятся составные ключи).
   CHECK-ограничения можно не переносить — почти все они это NOT NULL, который
   уже есть в `CREATE TABLE`.

3. **Ответ функции ограничен (~3,5 МБ), время жизни — секунды.** Вся база за
   один вызов не уедет: будет 502/504. Поэтому:
   - качай ПО ОДНОЙ таблице: `?action=db&table=NAME`;
   - большие таблицы — частями: `&offset=N&limit=M`;
   - порядок строк фиксируй `ORDER BY ctid`, иначе куски пересекутся или
     что-то потеряется;
   - в локальном скрипте сделай авто-дробление: при 502/504 уменьшай шаг
     1000 → 250 → 50 → 10 → 2.

4. **`INSERT` пиши пачками по 100 строк** — так файл читаемый и грузится быстро.

5. **Счётчики автономеров.** После данных обязательно `setval(...)` для колонок
   с `nextval` в DEFAULT, иначе новые записи начнут конфликтовать по id.

6. **Индексы и FK — отдельным файлом, ставятся ВТОРЫМ**, после заливки данных:
   вставка идёт быстрее и ключи не спотыкаются о порядок таблиц.
   При генерации индексов пропускай `*_pkey` и те, что уже созданы как UNIQUE, —
   иначе дубликаты.

7. **Список файлов в бакете получить НЕЛЬЗЯ**: `bucket.poehali.dev` не
   поддерживает листинг (`list_objects` вернёт одну заглушку). Иди от данных:
   пройди по ВСЕМ колонкам типа `text/varchar/json/jsonb` во всех таблицах и
   вытащи регуляркой ссылки на `cdn.poehali.dev`. Любой реально используемый
   файл записан ссылкой в базе.

8. **Не перебирай колонки по одной** — сотня отдельных запросов не влезает в
   таймаут. Склеивай в общий `UNION ALL` пачками по ~60 запросов, каждую пачку
   в `try/except` с `conn.rollback()`.

9. **Регулярка для ссылок:** `https://cdn\.poehali\.dev/[^\s"'<>)\\&]+` —
   обязательно обрывай на `&`, иначе HTML-мнемоники (`&quot;`) в текстах статей
   склеят несколько адресов в один.

10. **Файлы на CDN публичные** — ключи S3 нужны только для записи. `download.sh`
    работает на любой машине с `curl` без всяких токенов. Сделай его идемпотентным:
    повторный запуск докачивает только недостающее, неудачные ссылки пишет в
    `_не_скачалось.txt` (несколько 404 — норма, это битые ссылки в базе).

11. **Секреты в выгрузку не класть.** Только `.env.example` с именами переменных,
    значения переносятся вручную из раздела «Секреты».

12. **Тяжёлые таблицы** (логи, метрики, история цен) вынеси в список
    `HEAVY_TABLES` — по флагу `full=0` выгружать их только структурой, без данных.

## Что положить в README выгрузки

```bash
createdb myproject
psql myproject -f dump.sql       # структура и данные
psql myproject -f indexes.sql    # индексы и связи — ОБЯЗАТЕЛЬНО вторым
bash download.sh ./files         # файлы хранилища
```

Плюс раздел «как переключить сайт на свои файлы»: ссылки в базе ведут на
`cdn.poehali.dev`, их надо заменить `UPDATE ... replace(url, 'https://cdn.poehali.dev/projects/<КЛЮЧ>/bucket/', '/files/')` во всех таблицах, где они встречаются.

Плюс раздел про бэкенд: функции — это папки с `index.py` и точкой входа
`handler(event, context)`; на своём сервере поднимаются обёрткой на FastAPI/Flask,
которая превращает HTTP-запрос в `event`. Не забудь упомянуть, что облачный
прокси подменял `Authorization` → `X-Authorization` и `Cookie` → `X-Cookie`,
и что адреса функций фронтенд берёт из `src/lib/api.ts`.

## Как проверить, что всё работает

1. `?action=info` — сходятся ли числа строк с реальностью.
2. Прогнать локальный скрипт целиком, получить `выгрузка/`.
3. Поднять базу из дампа локально и сравнить `COUNT(*)` по паре ключевых таблиц.
4. Проверить, что `indexes.sql` накатывается без ошибок.
